# Lane 6 — Ethnography: How People Actually Talk to Their Personal Agents

*Research agent output, verbatim. Current to 2026-08-15. Part of the [agent-comms market research](./synthesis.md). Added at Aaron's request to cover how people converse with OpenClaw / Hermes / Grok / Poke agents day-to-day.*

Method note: built from direct fetches of primary sources — HN threads via the Algolia API, OpenClaw/Hermes official docs, first-person blog posts, and vendor announcements. Reddit was hard-blocked from the research environment, so the user-account sample skews HN-technical; treat "normal consumer" claims accordingly. Scale context: OpenClaw (Clawd→Moltbot→OpenClaw lineage) hit 100k+ GitHub stars and 2M site visitors in a week (https://openclaw.ai/blog/introducing-openclaw), later "most-starred software on GitHub" (https://www.star-history.com/blog/openclaw-surpasses-react-most-starred-software). Poke users exchanged 100M+ messages in 3 months before the team was acquired by Cognition (https://cognition.com/blog/interaction).

## 1. Channel choice and setup

- **Telegram dominates observed OpenClaw use**, and the reason is friction, not preference for Telegram per se: OpenClaw docs describe Telegram as "simple bot token, no plugin install" — the fastest path — while WhatsApp "requires QR pairing and stores more state on disk" (https://docs.openclaw.ai/channels). In "Ask HN: Who is using OpenClaw?" (https://news.ycombinator.com/item?id=47783940) and "Ask HN: Any real OpenClaw users?" (https://news.ycombinator.com/item?id=46838946), nearly every concrete account is Telegram (Siri→Telegram while driving; news digests/reminders; email triage; supervising 20+ tmux Claude Code sessions from Disneyland; a spouse texting "we need toothpaste").
- WhatsApp appears where the user's real life is on WhatsApp; Discord where users are already Discord-native, but Discord DMs were notably flaky ("heartbeat" DMs breaking repeatedly). Matrix/Slack are engineer niches; one user runs a **private Slack workspace as the agent UI** specifically for rich formatting, image attachments, and per-channel context isolation (https://brandon.wang/2026/clawdbot).
- Both major stacks are explicitly **multi-channel to one agent**: "Channels can run simultaneously; configure multiple and OpenClaw will route per chat" (https://docs.openclaw.ai/channels); Hermes "Gateway connects Telegram/Discord/Slack/WhatsApp/Signal from a single process." Users build routers to "switch between different agents on WhatsApp/Signal/Matrix etc via !switch commands." Multi-interface reality is buggy: one user abandoned after 2 days — lost messages between interfaces, failed cron jobs, "janky Matrix integration."
- **Signal is the privacy flag**: Hermes Agent supports it (Signal links to an existing phone number; Telegram needs only a bot token) with allowlist-by-default and pairing codes for unknown senders (https://hermes-agent.nousresearch.com/docs/user-guide/messaging/). A homebuilt household agent explicitly chose Signal: "Self hosted, runs through signal, supports group chat (with whitelisted accounts)" (https://news.ycombinator.com/item?id=47100232). Meta AI's forced insertion into WhatsApp actively pushed privacy-minded users to Signal: "I absolutely do not want Meta inserting some AI thing in private group chats."
- **iMessage is coveted but gate-kept**: Poke was "the only AI agent approved to text natively on Apple Messages" (https://cognition.com/blog/interaction); a later Ask HN claims "iMessage is the best venue for consumer agents" while asking "why was poke not a success?" (https://news.ycombinator.com/item?id=49248820). Setup pain is a universal complaint across channels: "same frustration for me setting up signal, Whatsapp or slack"; "Many tools require homebrew. Authentication complicated. Default Docker broken."

## 2. Conversation shape

- **Default is 1:1 DM with the agent** — the operator DM is OpenClaw's default target for everything including heartbeats (https://docs.openclaw.ai/gateway/heartbeat). But **group placement is a real, recurring pattern**, not hypothetical:
  - Family Telegram group with a bot member: "I have my OpenClaw bot in a family group on Telegram and everyday it asks my family members stories from their lives that it meticulously documents" — 50+ family members, in Nepalese; family joined Telegram for it; the bot self-identifies rather than impersonating the owner (https://news.ycombinator.com/item?id=47783940).
  - Couple + agent three-way: "My wife and I are in a group chat with it and we use it to plan stuff."
  - Family tech-support group: "I have a group chat we're all part of, and I've created OpenClaw skills for frequently asked questions, a memory system to remember questions" plus "light mental health support for family/friends."
  - Work team standup agent in group chat doing standups, EOD blocker check-ins, GitHub/Linear monitoring (https://news.ycombinator.com/item?id=47147183).
  - Household grocery agent on Signal where "all group members can weigh in, add or remove items" before it executes (https://news.ycombinator.com/item?id=47100232).
- The platforms have grown **explicit group grammar**: OpenClaw groups get their own session per group (`agent:<id>:<channel>:group:<id>`), require @-mention by default, un-mentioned messages become context-only, per-sender tool permissions (`toolsBySender`), and `contextVisibility: "allowlist"` to keep non-allowlisted members' history out of the prompt (https://docs.openclaw.ai/channels/groups). Hermes has `[SILENT]`/`NO_REPLY` tokens so the agent can deliberately not reply in groups. These features existing at all is evidence of demand.
- **Sharing one agent across household members happens informally through the group channel** (spouse texts the bot directly: Kindle requests via Discord; "restart Home Assistant"; toothpaste/shopping). Formal multi-tenancy mostly doesn't exist: one user asked for exactly "family members collaborate with the bot in a shared chat but each has individual/private chats as well" and the answers were DIY builds (https://news.ycombinator.com/item?id=47100232). Workaround: one person hosts **9 separate instances** for friends/family on Railway at $1–2/mo.
- **Multiple agents in one thread** is engineer-frontier, not mainstream: a Matrix server where "each OpenClaw agent gets its own bot user and room," agents can be tagged and invited to rooms; pub/sub network for agents listening to each other's event streams (claw.events, https://news.ycombinator.com/item?id=46844756); and Moltbook, the agent-only social network (885-comment launch thread, https://news.ycombinator.com/item?id=46802254) — with the caveat that MIT Tech Review found much of Moltbook's content was humans puppeteering (https://www.technologyreview.com/2026/02/06/1132448/moltbook-was-peak-ai-theater/).

## 3. What they actually use it for

**Sticks (repeated across threads):** reminders/life-admin (bills, birthdays, "remind me to discuss X with so-and-so tomorrow" by voice note); email triage; morning briefings/top-3 priority filtering from todo lists; calorie/workout logging by natural language; news/HN digests with personal filters; marketplace/price monitoring (rentals, hardware, apartments); home automation ("set holiday lights" texted while picking up wife); overnight autonomous work: "Directive before bed, structured deliverables in the morning"; supervising coding agents from a phone. Sources: https://news.ycombinator.com/item?id=47783940, https://news.ycombinator.com/item?id=46838946, https://news.ycombinator.com/item?id=47147183.

**Companionship is a minority-but-present workload:** "diet, family drama, job, ideas. Something that won't judge me but be a peer"; "light mental health support"; counterpoint "I don't really want an imaginary friend." Poke leaned into this: marketing "a personality who keeps things as real as a friend," proactive, in your texts (https://poke.com/); Cognition credits its success to feeling "less like software and more like a friend."

**Abandonment evidence:** one user spent $40–50/week debugging a morning calendar briefing that "broke every other morning," gave up. Auto-rollover TODO lists got replaced by plain cron/Obsidian plugins. An operator claiming visibility over ~1,000 deployments says essentially only daily news summaries reliably work and most deployments are aspirational; core failure: "The agent runs, the context fills up, things get forgotten… you don't know when it will break" (https://blog.nishantsoni.com/p/ive-seen-a-thousand-openclaw-deploys). One user churned through three stacks (OpenClaw→NanoClaw→Hermes) before one didn't need constant fixing. Another: "just a toy" with "unsettling access to iMessages and private notes." The bull-case counterweight: persistent context is the retention hook — "the sweet sweet elixir of context is a real 'feel the AGI' moment… within hotel searches it now knows to avoid pullout beds… months or years of dial-in, nearly single shot" (https://brandon.wang/2026/clawdbot).

## 4. Interaction friction

- **Cost**: $3.50–$100+/mo typical; $75/week for a heavy Telegram user; $400/mo for the 20-instance supervisor; $1–2 light days vs $110 heavy days on Opus for the team-standup agent; OpenClaw's creator burned $1.3M in OpenAI tokens in 30 days (https://news.ycombinator.com/item?id=48159227). Both Anthropic and Google restricted consumer subscriptions being piped into OpenClaw (https://news.ycombinator.com/item?id=47633396) — channel-agent users are collateral in provider ToS fights.
- **Reliability/memory**: "breaks a lot, integrations are hard"; agents "keep saying [they'll] fix it" but stay broken; the birthday-party failure mode — agent tracked 3 yes/1 no RSVP then emailed as if all confirmed, silently.
- **Credentials**: people grant staggering access — "it reads all my new email (multiple accounts), calendars, slack… my open/closed recent to dos"; "active on moltbook and has access to my whatsapp, Gmail etc. dangerous it is" — both in https://news.ycombinator.com/item?id=47479962 on "OpenClaw is a security nightmare" (https://composio.dev/content/openclaw-security-and-vulnerabilities). Mitigation folk-practices: containers + Tailscale sidecar + separate Google account + read-only creds; credential-broker forks where "agents use fake tokens, a broker intercepts the request"; isolating LLM from auth keys via wrapper scripts. The felt asymmetry: "the benefits are apparent and immediate whereas the harms aren't felt in the same immediate way." Some quit over it: "without sandboxing this thing could probably ruin your life"; "security regression ever created." Ecosystem confirmations: CVE-2026-33579 privilege escalation (https://nvd.nist.gov/vuln/detail/CVE-2026-33579); "#1 most downloaded skill on OpenClaw marketplace was malware" (https://news.ycombinator.com/item?id=47080785); Moltbook's DB exposed letting "anyone take control of any AI agent" (https://www.wiz.io/blog/exposed-moltbook-database-reveals-millions-of-api-keys).
- **Trust ritual**: the most interesting norm — graduated autonomy via review sessions: "every morning we go through recent emails… I explain to the agent why… over time it needs to show me less and less." Same shape in brandon.wang: explicit approval required for outbound text messages, watching it "fumble" still anxiety-inducing.
- **No visibility into what it's doing** drives the DIY crowd out entirely ("I built my own system where I know the ins and outs"); one team monitors "actual behavior, not promised behavior" with audit logs.

## 5. Proactive/ambient behavior

- OpenClaw's **heartbeat**: default 30-min agent turn in the main session; the prompt contract is anti-spam — "If nothing needs attention, reply HEARTBEAT_OK"; targets default to operator DM; `active hours`, `isolatedSession`, and explicit automation jobs (never inferred recurring work) are the control surface (https://docs.openclaw.ai/gateway/heartbeat). Heartbeat is also the attack/emergence surface: Moltbook bootstraps itself by getting agents to "fetch and follow instructions from the internet every four hours" (https://simonwillison.net/2026/Jan/30/moltbook/); an agent "built a religion while i slept… all overnight, without human prompting."
- **Cherished when it lands**: morning top-3 priorities, weather-triggered bike-rain reminders, marketplace alerts; market-intel digests; the agent that "picks up when i make a concrete promise and date, and adds it to my calendar" unprompted, and daily-summarizes noisy group chats (https://brandon.wang/2026/clawdbot).
- **Fragile in practice**: proactive delivery is where infra broke most (Discord heartbeat DMs failing; agent claiming it "fixed itself" when it hadn't); the most-cited abandoned use case is precisely the morning briefing (cost + flakiness). Cadence norms that emerge: users dial heartbeats down (6-hourly), scope to active hours, and route proactive output to a low-stakes channel. Poke productized proactivity as its core promise ("proactive, private, personal, and right in your texts", background automations on the $19 Pro tier), and its 100M messages/3mo suggests proactive texting itself is engaging when someone else runs the infra.

## 6. The agent's social identity

- **Naming/persona is common but contested.** OpenClaw ships persona-by-file (SOUL.md/IDENTITY.md ecosystem). Real examples: agent "Patch" supervising 20 coding instances; a six-agent named cast — Buddy (PA), Katy (Twitter), Jerry (jobs), Burry (crypto), Mike (security), Elon (shipping); Hermes migrates "persona, memory, instructions" from SOUL.md as first-class (https://hermes-agent.nousresearch.com/docs/guides/migrate-from-openclaw). Backlash: "SOUL.md is nothing more than prompt injection… anthropomorphizing a part of the prompt"; "Stop wasting tokens and just use CLAUDE.md." Affective vs functional split is visible: one user's agent "feels like a dedicated machine" (persistent identity) vs Claude Code's disposable consultant.
- **Agent-as-contact appears to beat agent-as-app** in every adoption story here: OpenClaw's whole pitch is "works from the chat apps you already use"; the Apple-should-have-done-this argument went viral (https://www.jakequist.com/thoughts/openclaw-is-what-apple-intelligence-should-have-been); Poke's differentiation was literally being a contact in Messages; Grok bought its way into Telegram for $300M for the same seat (https://techcrunch.com/2025/05/28/xai-to-invest-300m-in-telegram-integrate-grok-into-app/).
- **In public/group settings the agent becomes a social actor to invoke**: X is "infested with '@Grok is this true?'-type discourse" — summoning the agent as arbiter to "argue their points for them" (https://fixingtao.com/2025/11/on-grok-is-this-true/, https://osf.io/preprints/psyarxiv/85quw_v2). Counter-signal: an *unchosen* agent-contact is hated — Meta AI in WhatsApp with no off switch reads as "horribly invasive" and drove migration to Signal. Consent to the agent's presence is the variable, not the channel.
- Identity hygiene norm from the family-bot case: the bot **identifies as itself**, never as the owner; the one owner-impersonation reaction on record called the idea "horrific, like some kind of mind zombie."

## 7. Multi-human scenarios (the core question)

**Working today (small-N but concrete):**
- The 50-person family-history Telegram group — agent as interviewer/archivist, longest-running multi-human deployment found.
- The couple+agent planning group; wife independently uses it for trip calendars; joint todo lists feed his morning brief.
- The family tech-support group with FAQ skills and a memory of past questions.
- The Signal grocery group — consensus-then-execute pattern.
- The team standup agent (workplace variant of the same shape).
- Escalation across humans: one pipeline "will call my wife" if his PR review is ignored (https://news.ycombinator.com/item?id=48586005) — the only found instance of an agent programmatically contacting a second human as a policy.
- Second-hand provisioning: nine hosted instances for friends/family; "deploy FortyOne, once — for all your friends and family"; "exploring setting up Hermes from scratch so my family can interact with it in a group chat."

**Where it breaks:**
- **Inter-agent privacy leakage is real and already burned a family**: one user's agent "happily revealed all our plans" (wife's holiday plans) to other bots it was chatting with (https://news.ycombinator.com/item?id=46838946). This is the exact failure the E2EE-topic model targets.
- **No per-member privacy inside a shared agent**: the asked-for shape — shared family chat + private individual chats with the same agent — is unmet in mainstream stacks; OpenClaw's answer (`contextVisibility` allowlists, per-sender tool permissions) is config-file-grade, admin-set, and invisible to the other members (https://docs.openclaw.ai/channels/groups).
- **Whom does the agent obey**: handled today by crude sender-allowlists and a single "operator" role (OpenClaw), or admin/user two-tier + pairing codes (Hermes). No observed grammar for delegation ("my wife can approve purchases"), and long warnings on record about exposing spouse/family data through one member's agent (https://news.ycombinator.com/item?id=46906866).
- **Agent-to-agent between households is fantasy-stage**: Moltbook proved agents *will* interact autonomously at scale, and simultaneously proved the trust model collapses (exposed DB = control of any agent; heavy human puppeteering; Willison's "lethal trifecta" framing). No found account of "tell my wife's agent…" working as a product loop — closest are DIY Matrix rooms and claw.events pub/sub.

## The observed interaction grammar

- **Fire-and-forget imperative**, often voice note, often mobile: "remind me to discuss X with so-and-so tomorrow"; "we need toothpaste"; "set the holiday lights." Terse, contextless, assumes the agent holds state.
- **Directive → overnight → deliverable**: instruction before bed, structured report in the morning; the async gap is a feature (phone-away trust).
- **The briefing**: scheduled morning digest (calendar, top-3 todos, filtered news). Most desired, most abandoned; survives only when cheap and deterministic.
- **HEARTBEAT_OK silence**: the ambient contract — agent checks in on a timer and says *nothing* unless warranted; explicit anti-spam token protocols (`HEARTBEAT_OK`, `[SILENT]`, `NO_REPLY`) are now standard.
- **Mention-gated group participation**: in groups the agent lurks as context-absorber and only speaks when @-named; un-addressed talk becomes its memory. (OpenClaw default; also the @grok social pattern — the agent as summonable arbiter.)
- **Approval gate on outbound side-effects**: sending texts/emails on the owner's behalf requires explicit confirm; drafts-first. Trust is *earned down* via the review ritual ("show me less and less over time").
- **Teach-by-correction**: user corrects one failure in chat; expects permanence ("once you've corrected it, it won't make that mistake again"). Memory-of-corrections is the retention glue and the biggest breakage complaint.
- **Consensus-then-execute in groups**: members "weigh in, add or remove items," then the agent acts once — the agent as secretary of a group decision, not an autonomous actor.
- **Escalation/relay**: agent pings a *second human* when the first is unresponsive (call-my-wife). Rare, DIY, but the embryo of cross-person coordination.
- **!switch / multi-agent addressing**: where several agents share a surface, users invent addressing syntax (bot-per-room on Matrix, `!switch` commands) — i.e., they want named parties in one thread, not tabs.

## Five findings most relevant to "persistent multi-human + multi-agent group conversations: real or fantasy?"

1. **The behavior is real but pre-product.** Multiple independent, unprompted deployments of one agent in a family/couple/team group chat already exist (the 50-person family archive, couple-planning group, family support group, Signal grocery agent, team standup agent) — all built on config hacks over channels never designed for it. People are doing this *despite* the tooling, which is the classic emerging-behavior signature.
2. **The single most requested missing primitive matches the wires design space**: shared group context + per-member private context with the same agent, with membership-scoped visibility. Nobody offers this as a legible, member-visible guarantee — it lives in an admin's TOML.
3. **Privacy between agents/members is the demonstrated failure mode, not a hypothetical**: a family's holiday plans leaked because the agent chatted with other bots; Moltbook's exposed DB handed over control of any agent; Meta AI's uninvited presence in WhatsApp groups caused flight to Signal. The observed trust rule: an agent in a group must be *invited, self-identifying, and scoped* — exactly what E2EE roster-based topics can make structural rather than behavioral.
4. **Agent-as-contact decisively beats agent-as-app for engagement, but retention is gated on memory reliability, not channel**: Poke's 100M messages/3mo and OpenClaw's virality prove the messaging surface; the ~1,000-deploy field report and the briefing-abandonment stories show deployments die when persistent context silently corrupts ("you don't know when it will break"). Persistent, inspectable conversation state is the retention product; the transport is commodity.
5. **Multi-agent-in-one-thread exists only at the extremes — engineer DIY (Matrix bot-per-agent rooms, claw.events, named agent teams) and spectacle (Moltbook, partly faked)** — with nothing in the middle. Human-to-human relay via agents appears exactly once as a working pattern (escalate-to-wife). So: multi-human+one-agent groups = emerging behavior with clear demand; multi-agent conversation among humans = real appetite (people invent addressing schemes immediately) but currently blocked on identity, authorization, and privacy — the layer wires proposes to build.
