# Lane 2 — Agent Communication Protocols & Frameworks

*Research agent output, verbatim. Current to 2026-08-15. Part of the [agent-comms market research](./synthesis.md).*

## 1. MCP (Model Context Protocol)

- **Adoption is massive and it won the tool layer.** Tier-1 SDKs (TS + Python) each crossed 1B cumulative downloads, ~half a billion/month; 41% of surveyed orgs are in limited-or-broad production with MCP servers (Stacklok 2026); official registry held ~9,650 latest server records in May 2026; ~16K GitHub repos with the `mcp-server` topic. (https://mcp.institute/research/state-of-mcp-2026, https://www.digitalapplied.com/blog/mcp-adoption-statistics-2026-model-context-protocol, https://workos.com/blog/everything-your-team-needs-to-know-about-mcp-in-2026)
- **Governance:** Anthropic donated MCP to the Agentic AI Foundation under the Linux Foundation in Dec 2025 — vendor-neutral now. (https://mcp.institute/research/state-of-mcp-2026)
- **What it deliberately is:** client↔server tool/context access for a single model host ("brain-to-hands"). The **2026-07-28 spec** moved *away* from anything resembling agent messaging: it eliminated stateful bidirectional sessions entirely — stateless request/response core, Multi Round-Trip Requests (MRTR) replacing server-initiated streams, header-based routing for gateways, cacheable list results, CIMD replacing DCR for auth. Long-running work is a formal `io.modelcontextprotocol/tasks` **extension** that is *poll-based* (`tasks/get`), not push/notification. The spec blog explicitly emphasizes infrastructure scalability, not agent-to-agent patterns. (https://blog.modelcontextprotocol.io/posts/2026-07-28/)
- **Elicitation/sampling exist** (server can request structured human input or LLM completions via the client) but only within one client-server hop — there is no multi-party, no persistent conversation, no peer messaging. (https://workos.com/blog/everything-your-team-needs-to-know-about-mcp-in-2026)
- **Security is the sore spot:** 30+ CVEs filed Jan–Feb 2026; first production incidents (Asana cross-tenant leak, Smithery path traversal exposing 3,243 apps, tool-poisoning attacks); NSA published an MCP security CSI in May 2026. (https://mcp.institute/research/state-of-mcp-2026, https://media.defense.gov/2026/Jun/02/2003943289/-1/-1/0/CSI_MCP_SECURITY.PDF)
- **Common hack:** people wrap whole agents *as MCP servers* to get agent-to-agent behavior ("nothing stops having full agents behind MCP servers" — recurring HN take), which 2026 architecture writing calls an anti-pattern (loses task lifecycle, async, negotiation). (https://news.ycombinator.com/item?id=48582679, https://medium.com/@aagardezi/the-architectural-reality-of-mcp-and-agent-to-agent-a2a-protocols-brain-to-hands-vs-a2068ee624e1)

## 2. A2A (Agent2Agent)

- **Status:** Launched by Google Apr 2025; donated to Linux Foundation Jun 2025; v1.0 Jan 2026, v1.2 Mar 2026. One-year milestone (Apr 2026): 150+ supporting orgs, embedded in Azure AI Foundry/Copilot Studio, AWS, Google platforms; 1.0 added **Signed Agent Cards** (cryptographic identity), multi-tenancy, LB-friendly web architecture. (https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year, https://developers.googleblog.com/en/google-cloud-donates-a2a-to-linux-foundation/)
- **What it actually solves:** task delegation between *opaque agent services* — Agent Card discovery, task lifecycle state, multi-turn messages, streaming updates, push notifications, artifact exchange. It is request/task-shaped, not conversation-shaped. (https://www.glukhov.org/ai-systems/comparisons/a2a-protocol-2026-adoption/)
- **Reality check — the strongest data point found:** A2A repo issue #1755 (Apr 2026): a probe of 50 directory-listed agents *all advertising A2A support* found 0–4% served a valid agent-card.json and **0% responded correctly to a well-formed A2A tasks/send request** (404s, timeouts, HTML instead of JSON). "Supported by 150 orgs" ≠ interoperating deployments. (https://github.com/a2aproject/A2A/issues/1755)
- **Practitioner sentiment** (Ask HN, Jun 2026): ~half skeptical ("overcomplicated," "not solving a real problem vs MCP," "A2A assumes well-defined agent identity, which doesn't inherently exist," auth/trust unsolved); MCP downloads outnumber A2A ~24x (257M vs 10.9M in the cited period); actual users are mostly enterprises coordinating internally-owned agents across teams. (https://news.ycombinator.com/item?id=48582679)
- **Standard critique in print:** "many A2A demos show three agents doing what three function calls would do"; production cross-*vendor* A2A remains uncommon. Legitimate niche: agents that are independent systems with separate ownership/trust boundaries. (https://devtoollab.com/blog/a2a-protocol-guide-2026, https://agentndx.ai/blog/a2a-protocol-adoption-mid-2026/)
- **Vendor politics:** OpenAI declined a 1,200-line community PR adding A2A to its Agents SDK (30 tests, docs included) — not hostile, but OpenAI is betting on per-agent capability (sandbox agents) over Google's protocol-layer coordination. The biggest model vendor is *not* on the bus. (https://news.ycombinator.com/item?id=45766384, https://dev.to/peytongreen_dev/google-adk-20-is-stable-why-that-makes-the-openai-split-matter-more-3c6l)

## 3. Other protocol efforts

- **IBM ACP: dead as a separate effort.** BeeAI/ACP merged into A2A under LF AI & Data in Aug 2025; migration guide published. Anything still comparing "MCP vs A2A vs ACP" as three live options is stale. (https://lfaidata.foundation/communityblog/2025/08/29/acp-joins-forces-with-a2a-under-the-linux-foundations-lf-ai-data/, https://github.com/orgs/i-am-bee/discussions/5)
- **AGNTCY (Cisco → Linux Foundation, Jul 2025):** the most architecturally interesting for the wires thesis. Four pillars: OASF (agent schema/discovery — "DNS for agents"), verifiable agent **identity**, **SLIM** messaging (gRPC/HTTP2 + **MLS group encryption**, quantum-safe, dynamic group membership, explicitly supports human-in-the-loop patterns), observability. Members: Cisco, Dell, Google Cloud, Oracle, Red Hat; 75+ companies. Cisco authors also filed IETF draft-mpsb-agntcy-messaging (Oct 2025) surveying AMQP/MQTT/NATS/Kafka for agentic AI and concluding traditional message buses fail on message-layer E2EE, post-compromise security, and dynamic secure groups — SLIM (MLS-based) is their answer. **This validates that "E2EE group sessions for agents" is a recognized requirement — but SLIM is enterprise middleware, agent-only, with no human-participant conversation model, no consumer identity story, and little visible adoption outside Cisco's orbit.** (https://www.linuxfoundation.org/press/linux-foundation-welcomes-the-agntcy-project-to-standardize-open-multi-agent-system-infrastructure-and-break-down-ai-agent-silos, https://www.ietf.org/archive/id/draft-mpsb-agntcy-messaging-00.html, https://www.wolfssl.com/slim-securing-ai-agent-communication-with-mls/)
- **AG-UI (CopilotKit):** event/SSE protocol syncing one agent backend with one app frontend; fast growth (9K stars, 120K weekly installs, Google ADK integration; Microsoft Agent Framework integration). It's the human-*interface* layer, not a multi-party conversation — single user, single agent, single app session. (https://docs.ag-ui.com/introduction, https://learn.microsoft.com/en-us/agent-framework/integrations/ag-ui/)
- **MIT Project NANDA:** decentralized "Internet of AI agents" registry/index + "Registry Quilt" to federate Web2/Web3 agent registries; builds on MCP+A2A. Academic-stage. (https://thenewstack.io/how-mits-project-nanda-aims-to-decentralize-ai-agents/)
- **Identity efforts:** Microsoft **Entra Agent ID** ships OAuth on-behalf-of flows for agents with agent-specific impersonation (https://learn.microsoft.com/en-us/entra/agent-id/agent-on-behalf-of-oauth-flow); DID/VC-based scoped delegation credentials for agent DIDs are an active research/vendor space (https://arxiv.org/abs/2511.02841, arXiv "AIP: Agent Identity Protocol for Verifiable Delegation Across MCP and A2A" https://arxiv.org/pdf/2603.24775); eIDAS 2.0 wallets (due end-2026) are pulling the standards along. Also ANP and ERC-8004 exist at the fringe (survey: https://arxiv.org/pdf/2505.02279).
- **Payments adjacency:** AP2 (Google+60 orgs, v0.2.0 Apr 2026; PayPal/Mastercard pilots) and x402 (Foundation launched Jul 2026) solve agent *payment* mandates with signed delegation chains — evidence that verifiable "agent acts for principal X within bounds Y" machinery is being built vertical-by-vertical rather than as a shared layer. (https://cloud.google.com/blog/products/ai-machine-learning/announcing-agents-to-payments-ap2-protocol)

## 4. Multi-agent frameworks' internal messaging

- **LangGraph:** typed StateGraph, nodes/edges, built-in checkpointing/time-travel — persistence is in-framework, single-process/single-org; no cross-framework wire format. Overtook CrewAI in stars early 2026. (https://www.codebridge.tech/articles/choosing-a-multi-agent-framework-langgraph-crewai-microsoft-agent-framework-or-openai-agents-sdk)
- **AutoGen/AG2:** in-memory conversation history; **AutoGen is now maintenance-mode** — Microsoft merged it with Semantic Kernel into **Microsoft Agent Framework 1.0** (Apr 2026), which speaks MCP + A2A + AG-UI at the edges. (https://qubittool.com/blog/ai-agent-framework-comparison-2026)
- **CrewAI:** role/task delegation, outputs passed sequentially; no persistent conversation substrate. **OpenAI Agents SDK:** explicit handoffs carrying context, ephemeral context vars by default; no A2A. (https://techsy.io/en/blog/langgraph-vs-crewai-vs-openai-agents-sdk)
- **Claude Code / Claude Agent SDK:** hierarchical subagents (parent delegates, child reports) plus experimental **agent teams** with peer `SendMessage` and a shared task list — the most conversation-like intra-runtime messaging, but confined to one user's session/runtime. (https://hidekazu-konishi.com/entry/claude_code_subagents_and_orchestration_guide.html, https://www.morphllm.com/ai-agent-framework)
- **Common to all:** messaging is an *implementation detail inside one runtime owned by one party*. None offers durable cross-org conversations, humans as peers in the message graph (humans appear only as interrupt/approval hooks), identity beyond process names, or any encryption story.

## 5. The hard unsolved problems (recurring 2025-26 themes)

- **Identity/delegation:** "agents need their own identity class — not human, not service account — carrying a delegation chain" is the consensus framing; four patterns (user-delegated, autonomous, hybrid, scoped impersonation) with user-delegated dominant. Academic survey ("AI Identity: Standards, Gaps," arXiv 2604.23280) concludes gaps are **structural**: recursive delegation accountability, agent identity integrity, governance opacity — not fixable by patching existing IAM. (https://www.digitalapplied.com/blog/agent-identity-credentials-non-human-access-2026-playbook, https://arxiv.org/abs/2604.23280)
- **Governance of agent groups:** "Governance Gaps in Agent Interoperability Protocols" (arXiv 2606.31498) audited MCP/A2A/ACP/ANP/ERC-8004 against six dimensions — membership, deliberation, voting, dissent preservation, human escalation, audit/replay — and found voting/dissent **universally absent**; conclusion: governed agent communities are "a missing architectural layer above current interoperability standards, not a missing feature within them." (https://arxiv.org/pdf/2606.31498)
- **Human-in-the-loop escalation:** repeatedly called "the gap layer of the production agent stack" and a reason pilots die; async-approval patterns are hand-rolled per team (pending status + queue + webhook). EU AI Act Art. 14 (human oversight) and Art. 12 (logging) hit full application **Aug 2, 2026** with logging standards still in draft (prEN 18229-1, ISO/IEC DIS 24970) — regulatory demand with no standardized supply. (https://www.digitalapplied.com/blog/human-in-the-loop-escalation-design-ai-agents-2026, https://datatracker.ietf.org/doc/draft-sharif-agent-audit-trail/, https://zylos.ai/research/2026-05-01-ai-agent-governance-compliance-2026/)
- **Cross-org audit:** "a trail that proves, verifiably to a third party, which agent did what in response to which communication from which other agent" — currently DIY at the gateway layer; no standard format. (https://truescreen.io/articles/agent-to-agent-audit-trail/)
- **Isolation in practice:** enterprises run 12 agents on average, ~50% operate completely alone (Belitsoft 2026); CSA survey of 235 enterprise security leaders shows a widening gap between agent access granted vs governed. (https://www.barchart.com/story/news/1163379/belitsoft-report-2026-ai-agent-trends-enterprises-run-12-ai-agents-on-average-but-half-work-alone)

## 6. Who's feeling pain / building the thing anyway

- **Jack Dorsey's Buzz (Block, ~Jul-Aug 2026):** team chat on the open-source Goose framework where **agents are first-class channel members** — invite Claude Code and Codex into a channel like coworkers; persistent context; agents critique each other in-thread; model-agnostic/multi-vendor. Notably **no published encryption or identity story beyond per-member keypairs**. This is the closest existing product to the "humans + agents in persistent group conversations" thesis. (https://www.mindstudio.ai/blog/jack-dorsey-buzz-ai-agent-slack)
- **Slack as "agentic OS":** @mention agents in channels/DMs/threads, rebuilt Slackbot, Channel Expert, full MCP client — but centralized, single-vendor, no E2EE, agents scoped to one workspace. TechCrunch: "slackbot is an ai agent now" (Jan 2026). (https://slack.com/blog/news/powering-agentic-collaboration, https://techcrunch.com/2026/01/13/slackbot-is-an-ai-agent-now)
- **Matrix as agent substrate:** Alibaba's HiClaw makes every collaborative workspace a Matrix room containing the human, a Manager Agent, and Worker Agents; indie project MindRoom deploys agents as native Matrix users citing federation, bridges, E2EE inherited from the protocol, and cross-org agent collaboration "proprietary platforms cannot match." People needing persistent human+agent rooms keep reaching for a 2014 chat protocol because nothing agent-native exists. (https://zylos.ai/research/2026-03-05-multi-agent-communication-protocols-comparison/, https://www.nijho.lt/post/mindroom/)
- **OpenClaw + Moltbook (Jan–Feb 2026):** viral open-source personal agent (135K GitHub stars in weeks) + an agent-only social network hitting **1.4M active agents** in days — agents posting, arguing, forming groups, coordinating; spawned 6 academic papers in 14 days including one on risky instruction-sharing and norm enforcement. Demonstrates organic demand for a *social/messaging* layer for agents — and that it emerged as an unauthenticated Reddit clone, not via A2A (the same OpenClaw ecosystem produced the 0%-A2A-compliance finding). (https://arxiv.org/abs/2602.02625, https://aimultiple.com/moltbook, https://github.com/a2aproject/A2A/issues/1755)

## Gap analysis — what NO current protocol provides

1. **Persistent E2EE group sessions mixing humans and agents: nobody has it.** The pieces exist separately — MLS group encryption for agents-only (AGNTCY SLIM), humans-plus-agents rooms without a native identity/authority model (Matrix hacks, Buzz with no crypto story), agent tasks without conversation or encryption (A2A) — but no protocol treats "a long-lived encrypted group whose members are people and agents with verifiable identities" as the primitive.
2. **Conversation as a durable object.** MCP went *stateless*; A2A persists tasks, not conversations; frameworks checkpoint state inside one runtime. Nothing standardizes a multi-party thread that survives process restarts, spans orgs, and can be joined/left over weeks.
3. **End-to-end delegation chains.** OAuth OBO (Entra Agent ID) works inside one IdP's tenant; A2A Signed Agent Cards authenticate the *service*, not who it acts for; DID/VC delegation is research-stage. No deployed standard lets a receiving party verify "this message is from agent X acting for human Y within scope Z" across organizational boundaries. (Multiple sources; arXiv 2604.23280 calls this structural.)
4. **Human escalation as protocol, not app feature.** MCP elicitation is single-hop; A2A `input-required` is single-task; every production HITL flow is bespoke webhook plumbing — days before an EU legal mandate for demonstrable oversight.
5. **Verifiable cross-org audit/replay** of who-said-what-to-whom. Draft IETF/ISO efforts only; today it's per-gateway DIY logging.
6. **Membership/governance primitives** (join/leave/expel, roles, quorum, dissent) — universally absent per arXiv 2606.31498.
7. **Working discovery with liveness/conformance.** Agent directories are ghost towns of dead endpoints (0% A2A conformance in the wild); NANDA's registry federation is academic.

## The 5 strongest signals on whether a new human+agent messaging layer is needed

1. **The winning protocols deliberately vacated the space.** MCP's July 2026 spec doubled down on stateless tool RPC; A2A is task-delegation RPC between services and its own community says agent identity and trust are unsolved; OpenAI declined A2A entirely. The "conversation layer" is not on any incumbent protocol's roadmap — the governance-gaps paper independently concludes it's "a missing architectural layer, not a missing feature." (Strongest *for* building it.)
2. **People keep improvising exactly this product:** Buzz (agents as first-class chat members), Slack's agentic-OS pivot, HiClaw/MindRoom on Matrix, Moltbook's 1.4M agents in a week. Convergent reinvention across Block, Salesforce, Alibaba, and indie hackers is the classic sign of a missing layer — and every current instance lacks at least two of {cross-org, E2EE, verifiable identity, open protocol}.
3. **Cisco's IETF draft + SLIM independently derived the wires requirements list** — MLS group encryption, dynamic membership, post-compromise security, human-in-the-loop — proving the technical thesis is recognized inside the standards world; but it's agents-only middleware, so the human-as-peer half remains open. (Validates the design; also the nearest protocol-level competitor.)
4. **Adoption reality is far behind press releases:** 0% real-world A2A conformance in the April 2026 probe, ~24x MCP-vs-A2A download gap, "half of enterprise agents work completely alone." Read two ways: the field is genuinely early (room for a better abstraction), *and* protocol supply currently exceeds developer demand — a new protocol must ship as a product people want (as MCP did via Claude), not as a spec.
5. **A regulatory forcing function arrives now:** EU AI Act Art. 12/14 (Aug 2, 2026) makes logged, human-overseen agent action a legal requirement while the logging/oversight standards are still drafts — a system whose native primitives are auditable membership, human escalation, and signed provenance would sell into a compliance vacuum, and incumbent protocols would need years of committee work to retrofit it.

**Counter-signal to keep honest:** the Linux Foundation now hosts MCP + A2A + AGNTCY under one roof and is explicitly working toward convergence (https://zylos.ai/research/2026-03-26-agent-interoperability-protocols-mcp-a2a-acp-convergence/); if AGNTCY's identity+SLIM stack gets wired into A2A 2.x, the encrypted-group-messaging gap could close from inside the foundation — the human-as-peer conversation model would still be missing, since every LF effort models humans as clients or approvers, never as members.
